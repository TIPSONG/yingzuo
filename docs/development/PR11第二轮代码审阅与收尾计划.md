## 3. 尚需修复的代码问题

行号、路径对应本轮 head；后续有提交以函数名重新定位。

### N01 · P1：暂停租约在异步等待期间生效，pump 仍能开始任务

`desktop/services/queue-service.cjs:70–84` 仅在 while 开头检查 leases。随后 await client.queue；等待期间维护取得暂停租约，waitForIdle 看到还没有 active task 就返回。queue 响应到达后 pump 没有重检租约，直接 runTask。

本轮隔离探针：让 client.queue 等待，取得 `maintenance:fixture` 租约并等待空闲，再返回空后端队列，观察到 `ranAfterMaintenancePause=true`，租约仍存在。探针没有发网络请求或运行真实任务。

这会使维护或模型移动与刚开始的任务重叠。新增租约本身尚未构成原子的提交屏障。

### N02 · P1：维护阻断只在内存，且没有核对 owned 后端中的外部任务

`maintenance-service.cjs:56–58` 使用 holds=[]，没有从事务／恢复日志重建。恢复失败后重启应用，之前的阻断消失。guardedRestore 成功后还会 releaseHolds 全部租约，没有确认本次恢复覆盖哪次失败和哪些根目录。

同文件 services 仅请求 system_stats 并核对 service ownership；waitForIdle 只看本应用 task 表。应用自己启动的 ComfyUI 如果正在执行原生画布／其他客户端任务，仍可能被维护停止。owned 服务不代表所有任务 owned。

### N03 · P1：旧版中断仍有相同的竞态

`queue-service.cjs` cancel 已增加 jobCancelSupported/cancelJob，这是正确方向。但 legacy 分支仍在两次 GET queue 后发送可能被后端解释为全局操作的 interrupt。最后一次 GET 与 POST 之间仍可切换到外部任务；再查一次不能提供原子目标取消。

上轮 D10 对已支持目标 job 接口的后端有改善，但不能把 legacy fallback 的“缩小窗口”写成完全修复。

### N04 · P1：模型移动恢复会删掉源路径的新内容

`maintenance-service.cjs:120–137` 的 recoverModelMoves 核对目标 hash 等于 journal 的旧 hash，就删除仍存在的源，没有核对当前源是否仍是原文件。

本轮在隔离目录创建三份样本：journal 记录旧内容 hash，目标保存旧内容，源路径保存后来产生的新内容。调用恢复后得到 `sourcePreserved=false`，目标仍为旧内容，结果却是 completed。使用的只是小文本假文件，没有访问或删除真实模型。

此外 main 在初始化阶段直接运行该恢复；恢复没有取得环境／任务保护，needs-attention 的记录也可能被删除。启动清理必须保护最新和唯一副本。

### N05 · P1：快捷使用路径绕过敏感快照处理

`task-service.cjs:163` 的普通入口经 redactSnapshot 再 queue.enqueue；但 `maintenance-service.cjs:194` 的 resources.quickUse 仍直接调用 taskService.queue.enqueue，并保存完整 UI/API 图。图里含 API key 时，此路径可以把明文写入快照。

这是从公开 API 到存储的可达调用链，不是仅存在一个没使用的辅助函数。所有生产提交入口必须经过同一快照政策。工作区、模板、导出等其他持久化路径也不能只因为 task.run 已脱敏就推断安全。

### N06 · P1：应用备份／恢复缺少跨文件一致性与失败启动隔离

app-backup.createAppBackup 直接复制多个目录，最后备份数据库，没有应用写入屏障或版本固定。复制期间新建模板／任务可能使数据库引用稍后创建的文件，而那些目录已备份完，单个 SQLite integrity_check 不证明整包一致。

`desktop/entry.cjs:25` 在恢复失败后仍 finally require main，继续按正常应用初始化；pending 标记改名后没有可用的应用恢复 resume 入口。多目录恢复中途失败，不能立即把混合版本数据当正常数据使用。

环境备份还保留了全局按目录名 models、扩展名 .bin 等排除的规则；Python 包内的同名目录／数据并不都是模型。备份根／staging／恢复根的交叠检查也未在环境 createBackup 中落实。上轮 R13 只能算部分实现。

## 5. 下一轮程序任务：S01–S10

继续使用 `feat/grovebot-impl` 与同一个草稿 PR #11，不合并任何 PR。先核对更新后的 head；若以下问题已修，以代码／检查证据标注，不重做。

### S01 · P1 · 真正的提交屏障

将取得“可开始任务”许可、状态进入 preparing、pause/waitForIdle 放到同一协调器下。所有 await 后至少重检 leases/paused/stopped 和任务仍 queued；最终获得执行许可与 active 登记须原子，不能在维护已获空闲确认后再进入 preparing。取得 GPU 锁等待期间也要纳入 in-flight 统计和取消。

检查：在 ready、后端 queue 请求、GPU acquire 三个等待点取得维护租约，均不能随后启动任务；waitForIdle 不早于已授权任务结束；释放维护租约不解除用户暂停。用延迟 Promise 精确编排竞态，不用随机 sleep。

### S02 · P1 · 持久化且绑定范围的恢复阻断

持久化事务失败／未完成恢复的 recovery gate，启动时在任务和服务可写操作前重建。恢复成功只解除对应 transaction、backup 和受影响 roots 的阻断；无关小备份恢复不能解锁整个环境。

维护／恢复／模型移动重新核对实际 queue 的全部 running/pending 和来源，owned Comfy 中有外部任务也阻止。服务自动启动、提交和维护使用统一 gate。读日志、导出诊断、进入恢复页仍可用。

检查：恢复失败→重启→点击运行／维护、恢复无关备份、owned 后端中的外部任务、状态核对失败；不丢失阻断，不误停止外部任务。

### S03 · P1 · 旧后端取消能力的明确边界

保留原子目标 job 接口。legacy 后端未证明支持原子目标 interrupt 时，不使用两次 queue 查询冒充保证。默认禁止不安全的运行中目标取消，给出限制／等待结束；如另提供全局中断，须独立明确用户动作和影响，不能伪装“仅取消这个任务”。

检查：最后一次 GET 后目标结束、外部任务开始，不能对其 POST 全局中断；取消后退出仍走真实终态／超时流程。不要只测试原子 job 分支。

### S04 · P1 · 模型移动启动恢复保护

journal 保存阶段、源身份和 hash、登记根及目标身份。删除源前重新核对源 hash／身份也等于所移动的旧文件；源变化则两份保留并标冲突。源缺失＋目标不完整、只有唯一副本等情况保留 journal 和可恢复现场。先校验 tmp/src/dest 根与路径，再做清理；启动恢复也取得同一环境 gate，保护加载中的文件。

检查：目标旧内容／源新内容、源同大小但变化、源缺失、目标损坏、journal 路径非法、恢复时任务运行；不删除任何唯一或更新后的内容。禁止拿真实模型做开发删除测试。

### S05 · P1 · 统一的提交与存储政策

提供一个公开 SubmissionService.prepare/enqueue/enqueueGroup，负责来源／revision、表单、参考素材、校验、输出身份和敏感字段引用。resources.quickUse 及其他接口只能调用它，不直接访问 queue.enqueue 或 task repository 写快照。

检查所有生产调用点以及工作区、模板和图导出。敏感值只能进入系统加密存储；快照引用可在提交时内存解析。表单 password 属性保留，不泄露到普通文本值／日志。

检查：含虚构 API key 的普通、快捷使用、批量、重试、采用润色入口；明文不进入 UI 图／API 图快照和导出，且恢复任务仍可运行。能力不可用时明确拒绝，不静默删除必需输入。

### S06 · P1 · 可恢复的一致数据包

在同一写入 generation／短暂应用写入屏障下捕获数据库、工作区和文件引用 manifest，再复制不可变内容。任务快照、模板版本、图和素材的引用闭包都要校验，不能只检查数据库完整性。

应用恢复失败后进入 recovery mode，禁止正常写入／生成，暴露相同 journal 的继续或回退入口；不要重建新 journal 从头重复覆盖。凭据备份边界如实展示。

环境备份按登记模型／input/output 根排除，而非全局名称或扩展名；Python 包 data.bin、包内 models 等必须可回滚。实际创建前拒绝备份、journal、staging、trash 位于受恢复 source 内，处理源目录嵌套并算真实空间。

检查：目录复制期间新保存模板／创建任务、关系文件与图同步、WAL、恢复每一步中断、Python 非模型 .bin、交叠目录与磁盘不足；每个数据库引用均能找到包内文件。

### S07 · P1 · 完成 D04 的所有入口与版本身份

检查：更改中文名／分组／顺序实际显示；键盘与按钮一致；旧图＋新表单不会串配；润色前后更改字段能正确反映到最终图；子图同号节点不串写。
