# P0 桌面接入验证与后续实施建议

日期：2026-09-22。本文记录当前代码结构、技术判断与实际操作证据。**P0 仍在进行中，尚未全部完成。**下文区分已实测路径、代码修复及待测项目，未填写或未完成的项目不能视为通过。

## 1. 阶段结论

桌面方案采用 **Electron + WebContentsView**，保持现有原生 JavaScript/CSS，不重写 ComfyUI 节点编辑器。当前 `package.json` 固定 Electron `44.4.3`，Node 要求 `>=22.12`；最终版本以锁文件和实际验证环境为准。

P0 已形成独立 Windows 窗口的开发实现：管理界面、真实 ComfyUI 视图、参数读取与回写、独立工作副本及本地 JSON 保存。原 A 测界面作为单独预览入口保留。**这些代码存在不等于全部验收通过，也不代表 P1/P2 已完成。**

选型依据是现有代码复用和同窗独立网页视图的控制能力；本机已有 Node，Electron 提供明确的 context bridge、沙箱和原生保存入口。Tauri 与 pywebview 仍可作为备选，但本阶段没有足够收益支持增加新语言与工具链。完整对比及官方来源见 [桌面方案调查](./desktop-options.md)。[Electron 网页嵌入](https://www.electronjs.org/docs/latest/tutorial/web-embeds)、[WebContentsView](https://www.electronjs.org/docs/latest/api/web-contents-view)

本轮已通过实际桌面操作确认独立窗口、真实画布、文生图基础参数回写、两张图往返切换保值、原生 JSON 保存回读及正常重启恢复。根画布拖动节点后使用 Ctrl+Z 撤销也已通过；修复标签身份持久化后再次正常关闭／重开，仍复用相同原生文档，没有新增标签。图片上传、原生下载、配置过的官方 App Mode、子图内直接编辑及异常快速切换仍待测。表单回写只能覆盖可靠映射的基础控件，不能据基础路径成功推断所有第三方控件兼容。

## 2. 开发启动

在项目根目录执行：

```powershell
npm ci
npm run desktop
```

已经安装依赖后，也可双击项目根目录的 `Start-Desktop.cmd`。它打开 Electron 应用窗口，不是浏览器网址快捷方式。P0 是源码开发入口，正式便携包／安装包仍按后续阶段交付。

先使用现有 ComfyUI 启动脚本启动服务，再在应用里选择“连接已有服务”。本阶段不自动启动 ComfyUI 或 LM Studio，也不停止既有服务。**P0 关闭窗口时保存草稿并退出应用；缩到托盘及“退出并停止绘图服务”在 P1 实现。**保存失败应保持窗口并显示错误，避免把退出当作保存成功。

默认配置：

```json
{
  "comfyRoot": "D:/agent/ComfyUI",
  "comfyUrl": "http://127.0.0.1:8188/"
}
```

需要修改时，在 `desktop/config.local.json` 写入上述字段后重启。文件不存在则使用默认值。P0 仅接受 HTTP 本机根地址，尚不提供任意远程 ComfyUI 接入；路径配置页面、连接测试及错误提示完善安排在 P1。该本机配置不应提交到仓库。

## 3. 架构与信任边界

```text
映作窗口
├─ 管理页面：yingzuo://app/desktop/workbench.html
│  └─ preload：逐项公开桌面操作 → 主进程校验 IPC 来源与参数
├─ ComfyUI：独立 WebContentsView / session → 本机 8188
│  └─ 无 Node、无管理 preload；保留自身 HTTP / WebSocket
└─ A 测页面：独立 WebContentsView / session → 本地资源协议

主进程
├─ 加载工作流 / 读取根图 / 参数回写 / 模式切换
├─ 工作副本、JSON 导入导出、原生对话框
└─ .local 草稿、恢复副本、下载与 Electron 配置
```

- 管理页 IPC 限定到指定窗口的主 frame 和固定工作台 URL；preload 不暴露通用 IPC、文件读写或命令执行器。ComfyUI 网页没有这些桥接权限。
- 所有网页视图保持 `nodeIntegration: false`、`contextIsolation: true`、`sandbox: true`、`webSecurity: true`。ComfyUI 的 Python 自定义节点仍运行在既有服务内，此桌面隔离不等于 Python 插件沙箱。[Electron 上下文隔离](https://www.electronjs.org/docs/latest/tutorial/context-isolation)、[进程沙箱](https://www.electronjs.org/docs/latest/tutorial/sandbox)
- 管理页和真实编辑器不同 origin，不直接共享 DOM。`comfy-bridge-source.cjs` 集中封装当前 ComfyUI 前端接口；主进程只请求固定操作，并校验返回图。
- 宿主标签有独立 UUID，桥接记录对应 ComfyUI 工作流，使用工作流路径与文档 ID 核对身份，以兼容 Vue／Pinia Proxy 包装。读取、模式切换与参数修改须核对身份；不能仅以节点编号相同认定是同一个工作副本。
- 原生视图边界由主进程限制在内容区域，切到参数表单或 A 测页面时切换可见性。高 DPI、窗口缩放、键盘焦点以及遮挡问题必须实际操作验证。
- 每个独立 session 单独注册本地资源协议；不同 partition 不能只依赖默认 session 的 handler。[Electron protocol 与 session](https://www.electronjs.org/docs/latest/api/protocol#using-protocol-with-a-custom-partition-or-session)

桥接是版本适配层，不是 ComfyUI 永久稳定的公共协议保证。前端升级后应重复执行本阶段验收，不能仅凭 HTTP 状态接口可达判断兼容。

## 4. 数据与恢复边界

| 位置 | 用途 |
| --- | --- |
| `.local/p0-baseline/` | 原部署保护文件、SHA256、仓库版本与小型代码差异 |
| `.local/desktop-workspace.json` | 桌面多标签工作副本及活动标签 |
| `.local/recovered-workspace-*.json` | 原草稿读取失败时，退出前保存内存工作区的独立恢复文件 |
| `.local/closed-workflows/` | 已关闭标签或检测到 ComfyUI 内部切换时的恢复 JSON |
| `.local/exports/` | 原生导出的默认目录、ComfyUI 网页下载目录 |
| `.local/electron-profile/` | 应用本地浏览器配置与 session 数据 |
| `desktop/config.local.json` | 本机 ComfyUI 路径、地址覆盖配置 |

这些本地数据不进入 Git。原有模板作为输入读取，编辑保存在副本中；复制标签必须深拷贝图，不能共享对象引用。JSON 工作副本当前上限 8 MB，同时最多 20 个标签，工作区文件上限 64 MB。API 格式的任务图尚不支持在 P0 自动转成可视节点图。

草稿采用先写临时文件、再替换正式文件的方式。读取已有损坏草稿时保留原文件并报告，不能用空白工作区静默覆盖。保存失败、切换失败、原生工作流身份变化以及正在回写参数时切换标签都属于重点回归场景。

P0 基线已在本机收集 **12 个保护文件，缺失 0**：5 个工作流、3 个启动／停止批处理、Gemma 说明、2 个节点源码文件及 1 份本地补丁。三个仓库的 HEAD/status/diff 另行记录。工具不复制模型权重、不收集 remote 或凭据存储；差异中的可识别凭据式赋值会脱敏。

```powershell
python tools/p0_baseline.py
python tools/p0_baseline.py --verify
```

重复运行保留已有基线，不覆盖。2026-09-22 本轮工具复核结果为 `PASS; 12 protected files`；Python 临时目录测试 **7 项通过**。Node 内置测试 **48 项通过**（含本机工作流集成检查），覆盖导入、兼容性、桥接与桌面工作区。这些自动检查不能代替下面的 UI 验收。

## 6. P1：桌面与服务控制，保留 3–4 个有效开发日

P0 降低了容器选型不确定性，但进程生命周期、托盘、配置持久化与故障恢复尚未交付，没有依据缩短原估时。

| 工作包 | 预计 | 具体交付与验收 |
| --- | --- | --- |
| 配置与服务所有权 | 1 日 | 配置 ComfyUI/Python/输入输出路径与 LM Studio 地址；读实际状态；区分既有外部服务和本应用启动进程 |
| 启停、日志与托盘 | 1 日 | 启动后等真正就绪；重复启动不复制进程；关闭缩托盘；托盘提供显示窗口、输出目录和明确退出 |
| 管理页融合与入口 | 1 日 | 将真实状态及控制并入既有界面；提供可双击的开发版入口；保留真实节点图与参数表单 |
| 故障回归与缓冲 | 0–1 日 | 端口占用、路径错误、启动失败、服务退出、保存失败、托盘退出时的进程状态 |

P1 要特别完成：只停止本应用明确拥有的服务，不按进程名清理整机 Python；连接外部已运行服务时显示所有权。关闭进托盘与退出并停止服务是不同动作。配置与用户数据要确定可写位置，不能把最终安装目录假定为长期可写目录。

交付门槛：无需手动找 BAT 即可完成正常启停和输出文件夹定位；故障提示能区分服务未启动、正在加载、连接失败；原 BAT 仍独立可用。此阶段不扩充在线模型下载、插件安装或升级恢复。
