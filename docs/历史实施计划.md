### 建议补充的功能（待用户讨论）

- **工作流依赖检查**：导入时列出需要的节点与模型、已具备的资源和缺失项，并提供可执行的处理入口。匹配不确定时允许手动指定，避免声称所有兼容性都能自动判断。
- **模板与使用副本分开**：使用模板时创建工作副本，保留未保存草稿，允许将满意的修改另存为新版本。模板可带中文名、缩略图、用途、标签与所需模型。
- **提示词收藏**：保存常用画风描述、编辑指令、Gemma 润色规则，方便在不同工作流间复用。
- **任务与生成记录**：显示等待、执行、完成、失败状态；图片关联提示词、seed、工作流及可获取的生成参数，便于复现。缺少元数据的图片明确提示。
- **版本恢复**：更新前记录 ComfyUI 版本、插件版本及 Python 依赖状态；保护本地修改，准备可恢复方案。执行时不自动覆盖现有 Gemma 插件修改。
- **下载管理**：如果支持在线安装，则提供进度、暂停／续传（依来源能力）、失败重试、目标目录和空间检查。

### 资源管理边界

- 插件是程序代码，需要管理来源、版本、启用状态及依赖。
- 模型文件按用途分类：主图像模型、LoRA、文本编码器、VAE、语言／视觉语言模型。
- GGUF 是文件格式，图像模型与语言模型要分别展示用途和加载方式。
- 已由 LM Studio 管理的 Gemma 优先记录位置与连接关系，避免重复复制或下载。
- 目录整理、移动、卸载涉及工作流引用，实施前需明确引用检查和恢复方式。

### 已确认的产品方向

1. **独立桌面软件**：管理页面与 ComfyUI 在同一个窗口里。
2. **完整资源入口**：既能管理本地文件、粘贴链接安装，也能在线搜索、浏览和下载插件及模型。
3. **双模式生成**：简洁表单与完整 ComfyUI 节点画布可切换。
4. **表单覆盖范围**：先做好现有工作流的表单，并允许为新工作流选择要显示的参数。
5. **更新策略**：提示有更新后由用户点击执行；更新前备份，失败可恢复。
6. **关闭行为**：窗口关闭默认缩到托盘；托盘提供“退出并停止绘图服务”。
7. **在线模型来源**：Hugging Face 和 Civitai 都接入。
8. **图片导出**：提供保留生成信息的原图，以及去掉生成信息的分享副本两种选择；保留原始生成文件。
9. **参考图收藏板**：参考素材只做收藏功能，收藏的图片集中放到一个板子中。不按此前建议扩展成标签、人物／画风／姿势／服装分类素材库。
10. **收藏板布局**：采用相册式自动排列，不做自由拖动缩放的画布。
11. **工作流模板来源**：除本地导入、自行保存外，还支持在线浏览和下载他人分享的工作流。具体来源及技术可行性待调研。
12. **模型存储**：下载时默认选择对应模型目录，允许下载前修改位置；现有模型沿用原位置。
13. **模板分类**：文件夹和标签都支持，并提供收藏与搜索。
14. **模板修改与保存**：打开模板先创建工作副本；修改自动存草稿；用户可选择更新原模板或另存新模板，保存历史可用于回退。
15. **任务队列与批量生成**：提供排队、进度、取消、失败重试；支持多段提示词及不同种子、参数的批量生成。绘图任务明确采用依次执行。
16. **模型与 LoRA 详情**：展示预览图、适用底模、说明、触发词、建议权重；允许手动补充信息，并在兼容工作流中快捷使用。适用范围和兼容性需实际检查。
17. **软件启动策略**：启动桌面软件先显示首页；用户选择工作流后，再启动该工作流需要的后台服务。
18. **工作流缺失依赖**：列出缺少的节点／模型、来源与可获取的下载大小，由用户确认后执行一键补齐；来源不明确时允许手动指定，不静默自动安装。
19. **Gemma 润色交互**：支持先润色、查看和修改后再生成，也支持自动润色后直接生成。
20. **新图片存放**：由启动台提交的任务默认按“日期／工作流”分文件夹保存，已有图片保持原位置。
21. **交付顺序**：分阶段交付；先做好启停、工作流切换、双模式和作品库，再逐步加入完整资源管理、在线下载、更新恢复等功能。所有已确认功能继续保留。

此处的桌面软件选择取代原计划“优先本地网页启动页”的产品形式。界面仍可采用网页技术，但用户面对的是统一桌面窗口。具体桌面框架尚未选定。

## 目标

做一个可以双击打开的统一入口，解决三个问题：

1. 启动、关闭 ComfyUI 和 LM Studio 比较麻烦。
2. 切换工作流麻烦，容易打开旧工作流，分不清是否带 Gemma。
3. 不方便找到生成图片及其所在文件夹。

用户已明确：“切换工作台”主要指 **切换 ComfyUI 工作流**。第一版只围绕绘图，不接入知识库、OmniDocs 或 Hindsight。

## 第一版功能

### 工作流入口（最高优先级）

用中文名称展示，点击后直接打开对应工作流，不再让用户手动查找、拖入 JSON。

| 显示名称 | 现有文件 |
| --- | --- |
| 文生图 | Qwen 2.1 Q6_K - Text to Image.json |
| 多图编辑 | Qwen 2.1 Q6_K - Multi Image Edit.json |
| 文生图 · Gemma 润色 | Qwen 2.1 Q6_K + Gemma - Text to Image.json |
| 多图编辑 · Gemma 润色 | Qwen 2.1 Q6_K + Gemma - Multi Image Edit.json |
| 只润色提示词 | Gemma 4 - Prompt Enhancer.json |

- 明确标注“直接使用提示词”或“先经 Gemma 润色”。
- 服务未启动时，点击入口后启动所需服务，等待就绪，再打开工作流。
- 普通文生图、多图编辑只需 ComfyUI；Gemma 工作流还需 LM Studio。
- 切换时保留用户当前未保存的修改，不直接覆盖正在编辑的画布。
- 尽量复用已打开的 ComfyUI 窗口，避免每次点击都新开一个重复页面。
- 提供工作流文件夹入口，方便用户以后添加或整理自己的工作流。

### 启停与状态

- 一键启动绘图服务。
- 分别启动、停止 ComfyUI 和 LM Studio 本地 API 服务。
- 显示“未启动 / 启动中 / 已就绪 / 失败”，失败时给出简短原因与日志入口。
- 提供释放绘图模型显存的操作，不必为了腾显存反复关闭整个程序。
- 后台启动尽量不弹命令行窗口，重复启动不产生多个实例。
- 关闭启动台界面与停止绘图后台是两个明确操作，界面说明各自作用。
- 如果 ComfyUI 正在生成，停止按钮应显示任务数量和中断提示，不能无提示杀掉任务。
- 只停止确认属于本套绘图环境的进程，不按 python.exe 等通用名称批量结束进程。
- LM Studio 的服务关闭、模型卸载、桌面应用退出要区分清楚，不把“停止 API”显示成“整个 LM Studio 已退出”。

### 生成图片

- 展示最近生成图片的缩略图、文件名和生成时间。
- 点击可查看大图。
- 每张图片提供“在文件夹中定位”。
- 提供“打开全部输出”“打开输入素材”快捷入口。
- 第一版只浏览，不实现批量删除、移动等文件管理功能。

## 技术方向与待解决项

建议独立放在 `D:\agent\image-launcher\`，与 ComfyUI 核心代码分开，提供一个明显的双击启动入口。优先采用轻量本地网页界面配合 Python 后台，复用现有 Python 环境，不引入大型框架。最终形式以实际启动便利程度为准。

后台只监听本机地址。启动、停止、打开文件夹采用固定操作及受限目录，不接受网页传入任意命令。需要做本地请求来源校验，防止其他网页调用启停接口。

**工作流直达是首先需要验证的技术点：**

- 不能仅打开 ComfyUI 首页后就声称“已切换工作流”。
- 已检查当前前端源码，尚未确认通用的 `?workflow=文件名` 入口，不应直接假定支持。
- 当前前端确实提供 `app.loadGraphData(...)`，且加载前会保存当前工作流状态；但具体如何切换到已存在的标签、保留草稿、防止重复标签，仍需验证。
- 优先使用 ComfyUI 已有能力；若不足，可做一个小型独立前端扩展，负责接收启动台的工作流打开请求，不修改 ComfyUI 核心。
- 跨窗口通信必须限定本地启动台来源，并校验工作流名称及路径。

## 验收标准

- 双击一个入口即可进入启动台，无需找多个 BAT。
- 五个工作流入口都能打开正确版本；带 Gemma 的入口能看到实际润色节点。
- 来回切换不会丢失未保存的提示词或覆盖原始工作流。
- 服务停止时点击工作流能自动启动所需服务；重复点击不重复启动实例。
- 正在生成时停止操作有明确提示，正常停止后相应端口和资源确实释放。
- 生成图片能在列表中看到，并能定位到 Windows 文件夹里的真实文件。
- 路径越界、非本机来源调用、未知启停操作被拒绝。
- 原来的启动脚本和工作流仍能独立使用。
