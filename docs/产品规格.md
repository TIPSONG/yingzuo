状态：规格讨论草稿；已制作阶段零 A 测前端，等待用户审阅美术风格。正式桌面容器和后端功能尚未接入。本文汇总已确认选择，并标明实施建议与待验证事项；不代表已实现或已验证全部功能。

## 1. 定位与范围

一个 Windows 独立桌面软件，把启动、工作流切换、ComfyUI 画布、简洁生成表单、插件与模型管理、模板、作品及参考图收藏放在同一个窗口。

2026-09-22 再次确认：当前 WebUI 仅为原型，最终必须交付可从桌面入口启动的 Windows 应用，管理页和 ComfyUI 同窗，具备托盘和真实服务控制；本地网址或浏览器快捷方式不等于应用交付。桌面应用开发版在服务接入阶段即提供，最终打包在发布验收时完成。

本轮只管理绘图环境，不接入知识工作台。复用当前 ComfyUI、LM Studio、模型文件和已有工作流。

已确认的核心使用流程：

1. 双击打开软件，先显示首页。
2. 选择工作流，按需启动 ComfyUI；需要 Gemma 时再启动 LM Studio 服务。
3. 在简洁表单或节点画布中编辑；切换模式保留同一份参数和草稿。
4. 直接生成，或先用 Gemma 润色。可查看修改润色结果，也可自动润色后生成。
5. 单次任务和批量任务统一排队，绘图任务依次执行。
6. 在作品库查看图片、生成信息、导出副本或打开所在文件夹。
7. 关闭窗口缩到托盘；使用“退出并停止绘图服务”明确停止服务。有任务运行时先提示。

## 3. 已确认的功能与行为

### 3.1 启停与桌面行为

- 启动软件先显示首页，点击工作流后按需启动相应服务。
- 管理页和 ComfyUI 在同一个桌面窗口内。
- 窗口关闭默认缩到托盘；托盘提供“退出并停止绘图服务”。
- 绘图任务依次执行。

实施要求：启动过程显示进度与失败原因；重复启动不能产生重复实例；有正在生成的任务时，停止操作先提示影响。区分 LM Studio 的 API 服务、模型实例和桌面应用状态，不能显示虚假的“全部已退出”。仅操作确认属于本环境的进程。

### 3.2 双模式与表单配置

- 简洁表单和完整 ComfyUI 节点画布可切换。
- “简洁创作”和“节点画布”在侧栏及首页提供并列入口，不能只突出表单、让节点模式难以找到；记住上次选择的模式，打开模板时沿用。
- 完整 ComfyUI 节点编辑能力保留，不以静态节点示意替代。A 测示意与真实编辑器必须明确区分。
- 创作工作区采用类似 ComfyUI 的顶部菜单和多工作流标签栏；用“＋”或“工作流 → 新建”添加标签，点击标签切换工作流。
- 新建工作流先打开空白起始页，提供三个选项：拖入／选择／粘贴 JSON、选择已有模板、新建空白节点画布。选择后在该标签继续，不覆盖其他工作副本；空画布不得预装示例节点。
- 节点画布顶部保留显眼的“运行”按钮和任务状态，与表单共用同一工作副本和队列。A 测运行仅演示；真实接入后执行当前工作流。无节点时禁用运行并说明原因。
- 每个标签独立保存提示词、参数、参考图、表单／节点模式及画布缩放。相同工作流可新建独立副本；普通打开优先切到已打开标签。
- 支持重命名、关闭、恢复最近关闭标签，以及刷新／重开后的草稿恢复。关闭标签不等于删除模板或工作流文件。
- 先为现有五个工作流做好表单。
- 新工作流允许用户选择要显示的节点参数。
- 表单支持参数中文名称、分组、默认值、显示顺序；映射随模板保存。
- 模板结构变化导致参数映射失效时明确提示修复。
- 两种模式共享工作副本，切换保留修改。

现有工作流：文生图、多图编辑、Gemma 润色文生图、Gemma 润色多图编辑、单独润色提示词。

### 3.3 Gemma

- 支持“润色 → 查看和修改 → 生成”。
- 支持“自动润色 → 直接生成”。
- 复用现有 LM Studio 与 Gemma 4 12B，不重复下载或移动模型。
- 保留当前显存协调方式与 8192 token 上下文配置。
- 当前已安装润色节点最多接收两张参考图；界面须明确这个实际能力，不把 Qwen 的参考图数量等同于 Gemma 节点支持数量。

### 3.4 工作流模板库

- 支持本地导入、自行保存，以及在线浏览和下载他人分享的工作流。
- 支持文件夹、标签、收藏与搜索。
- 打开模板创建工作副本，修改自动存草稿。
- 满意后选择“更新原模板”或“另存新模板”；保留手动保存历史供回退。
- 在线模板来源保留原始链接及作者信息；具体来源与覆盖范围需调研。
- 导入工作流检查缺失的节点、模型，显示来源与可获取的下载大小。
- 导入时提供问题清单：节点／子图位置、参数、原模型名、原因和替代建议，支持搜索与定位。区分缺失、用途不匹配、加载器或版本限制、动态参数以及无法核实。
- 替代模型按用途、架构、格式、量化加载器及接口匹配；GGUF 不代表用途或架构相同。语言模型另核对服务标识、文本／看图能力和上下文。
- 可直接调整的字段先展示原值与替换值，再应用到工作副本；自动复查，可撤销并导出修复副本。需要改加载器或连接结构的建议必须明确说明，未知兼容性不自动替换。
- A 测先用本机清单快照验证该流程；正式版接入实时节点定义、模型清单和运行前校验。
- 用户确认后执行一键补齐；未知来源允许手动指定。

实现时必须验证：从模板进入编辑器确实加载对应文件；反复切换不丢草稿、不覆盖原模板、不不断增加重复标签。

### 3.5 插件与模型管理

- 支持管理本地资源、粘贴链接安装，以及在线搜索、浏览、下载。
- 模型在线来源同时接入 Hugging Face 和 Civitai。
- 插件按 ComfyUI 自定义节点管理，支持目录来源与 GitHub 链接；具体与现有 Manager 的集成方式待验证。
- 模型按用途区分主图像模型、LoRA、文本编码器、VAE、语言／视觉语言模型。
- GGUF 是格式，图像 GGUF 与语言 GGUF 明确标识用途及加载方式。
- 默认自动选择对应下载目录，下载前可改位置；已有模型沿用原位置。
- 详情包含可获取的预览图、适用底模、说明、触发词、建议权重；允许手动补充。
- 对兼容工作流提供快捷使用操作；未知兼容性不能伪装成已确认。

实施建议：下载任务记录来源、版本、文件、目标目录与校验信息；支持进度、失败重试及来源允许的断点续传。取消或失败产生的临时文件不应被当作完整模型。目录移动、卸载等操作先检查引用关系；具体交互后续设计。

### 3.6 队列与批量生成

- 基础操作：排队、进度、取消、失败重试。
- 批量操作：多段提示词、不同种子、参数变化。
- 所有绘图任务依次执行。

实施建议：提交前显示展开后的任务数量；为每个任务保存独立的参数和工作流快照。修改当前表单不能改变已经提交的任务。重试默认使用原任务快照；失败原因应指向具体任务。重启后的待执行任务如何恢复，仍需讨论。

### 3.7 作品库与导出

- 浏览最近生成图片、查看大图，定位真实文件。
- 由启动台提交的任务默认按“日期／工作流”保存新图片；已有图片不移动。
- 导出提供两种选择：保留生成信息的原图，或移除生成信息的分享副本。
- 保留原始生成文件，导出副本不覆盖原图。
- 展示可获取的提示词、seed、参数及工作流，缺失元数据时说明缺失。

实施建议：输出目录采用稳定工作流标识配合显示名称，避免模板改名导致历史丢失；路径中的非法字符需处理。对不同保存节点先验证是否能可靠设定路径，不能静默改坏用户的高级保存设置。移除元数据时保留像素、透明通道和正常显示需要的色彩信息，实际格式逐一验证。

### 3.8 收藏板

- 参考素材只做收藏。
- 收藏图片集中进入一个相册式板子，自动排列。
- 不扩展成标签、人物／姿势／服装分类素材库，也不做自由画布。

收藏后的文件保留方式尚需确定：记录原文件位置，或保存独立收藏副本。这个选择影响原图删除后收藏是否还存在。

### 3.9 更新与恢复

- 有更新时提示，由用户点击才执行。
- 更新前备份，失败可恢复。
- 覆盖范围：ComfyUI、插件及其受影响依赖。
- 本地修改必须被保护，尤其是现有 Gemma 插件修改。
- 有生成任务时不直接执行更新。

实施要求：明确可恢复的程序、插件、依赖及设置范围。先验证备份与恢复，再启用更新功能。不能仅有版本号或 pip 列表就宣称能够恢复完整环境。模型文件作为外部资源复用，避免每次备份复制所有大模型。

## 5. 技术预研：已查证与未验证

### 已查证的现有能力

- ComfyUI 官方已有 **App Mode / App Builder**，可以选取节点输入、输出，形成简洁应用界面，并与同一 ComfyUI 后端和队列配合。优先验证是否能复用于本软件的双模式和表单配置，避免维护两套独立生成逻辑。[官方介绍](https://blog.comfy.org/p/from-workflow-to-app-introducing)
- ComfyUI-Manager 提供自定义节点管理、快照及命令行能力；其文档也说明非 Git 管理节点的快照支持存在不足。可作为集成基础，但仍需补足本地修改及依赖恢复验证。[官方仓库](https://github.com/Comfy-Org/ComfyUI-Manager)
- Hugging Face 提供模型检索与仓库信息接口，可用于站内资源搜索。[Hub API](https://huggingface.co/docs/hub/api)、[搜索接口指南](https://huggingface.co/docs/huggingface_hub/main/guides/search)
- Civitai 文档提供模型、版本、文件信息与下载接口；部分资源下载需要用户 API Key。下载时按照用户已有权限处理。[官方 API 文档](https://github.com/civitai/civitai/wiki/REST-API-Reference)

以上是文档层面的能力确认，尚未完成本机端到端集成。

### 开发前首先验证

1. 桌面容器嵌入现有 ComfyUI，确保画布、WebSocket、上传、下载、快捷键正常。
2. App Mode 对五个工作流、子图、图片输入、Gemma 的实际适配情况；表单与画布切换不丢状态。
3. 模板直达、工作副本与草稿行为；不能假定任意 `?workflow=` URL 均受支持。
4. 在线模型及工作流的搜索、分页、授权、跳转和下载行为；不能把官方模板目录当作全部社区来源。
5. Manager 集成、本地修改检测、备份与依赖环境恢复。

## 6. 分阶段交付（顺序已确认，阶段边界建议）

### 阶段零：A 测版前端，先确认美术风格（用户明确要求）

- 正式接入功能前，先交付可打开、可点击的前端预览，让用户查看配色、字体、布局、组件和整体美术风格。
- 预览覆盖首页、创作页（简洁表单／画布布局切换）、工作流库、资源管理、作品库、收藏板和设置的代表性界面；优先打磨日常使用最多的创作页与作品库。
- 使用示例数据演示导航、选中、筛选、详情和队列等交互，明确标识演示状态；演示操作不实际生成、安装、更新或删除文件。
- 用户先审阅并提出修改，确认视觉方向后再推进实际功能接入；A 测预览不等同于下列阶段的功能验收。

交付标准：给用户一个能直接打开的预览入口，实际查看页面和基本交互，完成美术风格审阅。

### 阶段一：日常创作可用

- 独立桌面窗口、按需启停、托盘。
- 五个现有工作流直接切换、工作副本和草稿。
- 简洁表单／画布，Gemma 两种润色方式。
- 基础任务队列、真实状态与日志。
- 作品浏览、目录定位、日期／工作流输出、两种导出。
- 必要的路径和服务设置。

交付标准：从双击软件到选择模板、生成、找到图片、停止服务，完整流程可独立使用。

### 阶段二：模板与资源完整管理

- 模板文件夹、标签、收藏、保存历史、自定义表单参数。
- 本地模型详情与快捷使用；插件管理。
- Hugging Face、Civitai 在线搜索下载与链接安装。
- 在线工作流模板与缺失依赖清单、确认后一键补齐。
- 参考图收藏板。

交付标准：本地和在线资源能形成“找到 → 安装／导入 → 检查 → 使用”的完整流程。

### 阶段三：批量与维护完善

- 多提示词／多种子／参数变化的批量任务，任务快照与重试。
- 更新提示、手动更新、备份、验证恢复。
- 下载恢复、失败诊断、完整设置与整体体验优化。

阶段安排可因技术依赖调整，但不能悄悄删减已确认功能。阶段零专用于视觉预览；阶段一至三均须交付实际可运行的功能，不得用演示界面替代功能验收。
